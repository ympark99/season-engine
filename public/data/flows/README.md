# 매출 흐름도 조사 결과

사이트 상세 화면의 [매출 흐름도]가 이 폴더를 읽는다 (서버가 raw.githubusercontent 로 15분마다 index.json 확인).
매일 아침 매크로 정기 작업이 `https://season-engine.vercel.app/api/stock?flow=queue` 의 예약 목록을 읽어 조사하고 여기에 올린다.

## index.json
```json
{ "KR:131290": { "at": "2026-10-13", "name": "티에스이" } }
```

## {m}_{code}.json  (예: KR_131290.json, US_NVDA.json)
```json
{
  "m": "KR", "code": "131290", "name": "티에스이",
  "at": "2026-10-13", "by": "Claude 정기 조사",
  "summary": "한두 문장 — 누구에게 팔아서 어디서 매출이 나오는지",
  "cust": [ { "name": "SK하이닉스", "code": "000660", "m": "KR", "share": null, "conf": "보도", "note": "근거 한 줄" } ],
  "supp": [ { "name": "SK하이닉스", "code": "000660", "m": "KR", "item": "HBM", "share": null, "conf": "보도", "note": "근거 한 줄" } ],
  "segs": [ { "name": "샘씨엔에스 (세라믹 STF)", "code": "252990", "m": "KR", "amt": null, "share": null, "note": "연결 자회사" } ],
  "unitSeg": "억원",
  "sources": [ { "t": "2025 사업보고서", "u": "https://..." } ]
}
```
- `cust` = 주요 매출처 (최대 8). `share` 는 매출 대비 % — 공시·실적 발표에 나온 숫자만, 모르면 null.
- `supp` = 주요 매입처·공급사 (최대 8) — 이 회사가 부품·소재·장비·원재료를 사 오는 곳 (예: 엔비디아 ← HBM은 SK하이닉스, 파운드리는 TSMC). `item` 은 사 오는 품목, `share` 는 매입 대비 % (공시에 나온 숫자만, 모르면 null), `conf` 는 아래와 같은 기준. 화면에서는 매출 파이프라인 아래 [주요 매입처] 목록으로 보인다.
- `conf` = `공시`(사업보고서·10-K·실적 발표에서 확인) · `보도`(기사·IR·리포트) · `추정`(비공개 거래처를 검색으로 유추).
- `segs` = 사업부·제품·연결 자회사 (최대 8). `amt` 는 금액(국내 억원, 미국 백만 달러, unitSeg 로 표시), `share` 는 매출 비중 %.
- `code`·`m` 을 넣으면 화면에서 눌러 그 종목으로 이동한다 (국내 6자리, 미국 티커).

## 비공개 거래처·매입처 추정 규칙
공시에 이름이 'A사'·'고객 A'·'영업기밀'로만 나오는 거래처·매입처는 비워 두지 말고, 조사해서 누구일지 **추정해 넣는다** (사용자 요청).
- 이름을 알 수 없으면 그 업종의 실제 후보를 기사·업계 구조(경쟁사 과점 구조, 최종 사용자, 공급 계약 보도, 회사 IR 발언 '유럽계 업체' 등)로 좁혀 넣고 `conf` 는 반드시 `추정`, `note` 에 유추 근거 한 줄과 '공시·보도로 확인된 것은 아님'을 적는다.
- 직접 고객이 프로브카드·모듈·장비 업체처럼 중간 단계면, 그 뒤의 최종 사용자(반도체 제조사 등)도 `cust` 에 `(최종 사용자)` 표시로 넣는다. 한 칸에 여러 곳을 묶을 때는 이름에 모두 적는다.
- 추정 항목의 `share`·`amt` 는 반드시 null — 숫자를 지어내지 않는다. 확인된 보도 수치는 `conf: 보도` 로 note 에 연도와 함께 쓴다.
- 근거가 전혀 없는 추측(그럴듯해 보이는 이름 나열)은 넣지 않는다. 'A사 (비공개)' 로 두는 편이 낫다.
- 8개 제한 안에서 확인된 항목(공시·보도)을 먼저, 추정은 그 뒤에 둔다.
