# 경쟁·기술 조사 (상세 화면 '경쟁·기술' 탭 · 대시보드 '다가오는 체크포인트')

매일 아침 '경쟁·기술 갱신' 정기 작업(Claude)이 내 목록 종목을 확인해 이 폴더에 올린다. 사이트는 정적 파일을 그대로 읽는다 (서버 조사 없음, 종목 조회 때 조사 안 함).
내 목록에 있는데 파일이 없는 종목 = 신규 → 다음 날 아침 배치에서 처음 조사한다.

## index.json
```json
{
  "KR:006400": { "name": "삼성SDI", "theme": "2차전지", "at": "2026-10-14", "full": "2026-10-14", "grade": { "g": "B", "label": "경쟁력 양호", "why": "…" },
                 "cp": [ { "id": "us_lfp_ess", "d": "2026-10", "what": "미국 LFP ESS 셀 양산 시작", "kind": "양산", "status": "진행" } ] },
  "_meta": { "rev": 1, "refreshDays": 7, "runs": [ { "d": "2026-10-15", "targets": 79, "newN": 3, "changed": 6, "deep": 6, "full": 11, "sectors": 32 } ] }
}
```
- `cp` 는 그 종목 파일의 checkpoints 중 status 가 완료·취소가 아닌 것만 (대시보드 위젯용 요약).
- `_meta.runs` 는 최근 30회. `refreshDays` = 변화 없는 종목 전체 갱신 주기(처음 7일, 변화가 적으면 14일로).

## {m}_{code}.json
```json
{
  "m": "KR", "code": "006400", "name": "삼성SDI", "theme": "2차전지",
  "at": "2026-10-14", "full": "2026-10-14", "by": "Claude 정기 조사",
  "position": "한두 문장 — 경쟁 구도에서 지금 어디에 서 있고, 이번 분기 관건이 무엇인지",
  "grade": { "g": "B", "label": "경쟁력 양호", "why": "종합 판단 근거 두세 줄 — 강점과 약점을 같이" },
  "peers": [ { "name": "LG에너지솔루션", "m": "KR", "code": "373220" }, { "name": "CATL", "m": null, "code": null } ],
  "axes": [
    { "k": "ESS 안전", "me": "이 회사", "vs": "경쟁사", "verdict": "우위", "conf": "보도", "src": [0],
      "chg": [ { "d": "2026-10-14", "note": "판정을 바꿨으면 왜 바꿨는지 한 줄" } ] }
  ],
  "checkpoints": [
    { "id": "us_lfp_ess", "what": "미국 인디애나 LFP ESS 셀 양산 시작", "d": "2026-10", "kind": "양산",
      "status": "진행", "conf": "공시", "src": [1],
      "log": [ { "d": "2026-08-05", "s": "예정", "note": "2분기 콜: 10월 양산·연내 공급" } ] }
  ],
  "metrics": [ { "k": "비중국 EV 배터리 사용량", "v": "13.6GWh (−32%)", "asof": "2026-08", "src": [2] } ],
  "updates": [ { "d": "2026-10-14", "note": "그날 확인한 진척 한 줄", "src": [3] } ],
  "sources": [ { "t": "문서 제목", "u": "https://...", "d": "2026-09-28" } ]
}
```
- `grade` = 경쟁·기술 종합 등급 (상세 화면 맨 위 태그). `g` A·B·C·D ↔ `label` 경쟁력 우위·경쟁력 양호·경쟁력 보통·경쟁력 열세. axes 판정·점유율·실적 모멘텀·다가오는 체크포인트 위험을 종합해 정하고, 바뀌면 updates 에 이유를 남긴다.
- `verdict` = `우위` · `선두권` · `동등` · `열세` · `불확실` 중 하나. `conf` = `공시` · `보도` · `추정` (회사 목표치는 문장에 '목표'라고 쓴다).
- `checkpoints[].d` = `YYYY-MM-DD` 또는 날짜를 모르면 `YYYY-MM`(그 달 중) · `YYYY-Qn`(그 분기 중) · `YYYY-H1`·`YYYY-H2`(반기 중) · `YYYY`(그해 중). `kind` = 양산·실적·수주·인증·출시·규제·임상·기타.
- `status` = `예정` · `진행` · `완료` · `지연` · `취소`. 바뀔 때마다 `log` 에 한 줄 추가 (지연이면 이전 날짜도 note 에). `log` 는 최근 20개.
- `updates` = 날짜별 진척 (최근 30개, 최신이 앞). `axes[].chg` = 판정이 바뀐 이력 (최근 10개).
- `src` 는 `sources` 의 번호(0부터). 출처 없는 숫자·판정은 쓰지 않는다. 파일 안에 증권사·애널리스트 이름은 쓰지 않는다.
- `peers[].m`·`code` 는 사이트에서 눌러 이동할 상장사만 (국내 6자리, 미국 티커). 해외 비상장·중국 상장사는 null.
