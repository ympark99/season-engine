# 밸류에이션 조사 가정 (상세 화면 '밸류에이션' 탭 · 목록 '적정가' 태그)

적정가 **계산은 서버가 한다** (`lib/valuation.js`, 같은 재료·가정이면 늘 같은 값). 이 폴더에는 계산에 넣을 **가정과 근거만** 둔다.
매일 아침 '경쟁·기술 갱신' 정기 작업(Claude)이 아래 때만 조사해 올린다 (매일 조사하지 않음):
- 처음 조사하는 종목 (경쟁·기술 신규 전체 조사와 같은 날)
- 실적 발표 체크포인트(kind 실적)가 `완료`가 된 뒤 — 가이던스·설비투자 계획이 바뀌는 때
- 파일이 120일 넘게 안 바뀐 종목
- 파일이 없는 기존 종목 (하루 15종목까지 차례로 채움)

금융(은행·증권·보험·지주)·리츠·코인 테마는 DCF 대상이 아니라 조사하지 않는다. 파일이 없으면 서버가 유형별 자동 가정으로 계산하고 화면에 '조사 전 — 자동 가정'으로 표시한다.

## index.json
```json
{ "US:MU": { "at": "2026-10-19", "name": "Micron Technology" } }
```
`python3 scripts/intel/check_val.py` 가 파일들로 다시 만든다 (서버는 목록에 있는 종목만 파일을 받는다).

## {m}_{code}.json
```json
{
  "m": "US", "code": "MU", "name": "Micron Technology",
  "at": "2026-10-19", "by": "Claude 정기 조사", "basis": "FY26 4분기 실적(2026-09-30) 뒤",
  "type": "cyc", "typeWhy": "메모리 — 가격이 수급으로 정해지는 경기민감 업종",
  "mid":  { "om": 32, "why": "과거 두 사이클 영업이익률 중앙값 22% + 장기공급계약 확대", "conf": "추정", "src": [0, 3] },
  "peak": { "years": 1.5, "why": "2017~18·2021 정점 마진 지속 평균 약 1.5년", "conf": "보도", "src": [3] },
  "trough": { "om": 5, "why": "2023년 바닥 영업이익률", "conf": "공시", "src": [4] },
  "capexR": 25, "tax": null, "g": null, "wacc": null,
  "scen": {
    "bull": { "p": 25, "why": "장기공급계약 50% 달성 · 업계 증설이 FY30 이후로 밀림", "g": [null, null, null, 5, 0], "om": [null, null, null, 70, 55] },
    "base": { "p": 50, "why": "FY29부터 국내 신규 팹·CXMT 증설로 가격 하락", "g": [], "om": [] },
    "bear": { "p": 25, "why": "하이퍼스케일러 설비투자 둔화 + 공급 증가가 FY28에 겹침", "g": [null, -15, -25], "om": [null, 60, 30] }
  },
  "facts": [ { "k": "가이던스", "v": "FY27 1분기 매출 615억$, 매출총이익률 86%+", "conf": "공시", "src": [0] } ],
  "sources": [ { "t": "문서 제목", "u": "https://...", "d": "2026-09-30" } ]
}
```
- 숫자는 모두 **% 단위 숫자** (32 = 32%). 모르면 `null` 이나 키를 빼면 서버 자동 가정을 쓴다.
- `type` = `cyc`(경기민감) · `growth`(고성장) · `mature`(성숙) · `loss`(적자) · `na`(DCF 대상 아님). 빼면 서버가 테마·재무로 정한다. 바꿀 때만 넣고 `typeWhy` 에 이유.
- `mid.om` = 유형별 장기 영업이익률 — 경기민감은 **사이클 중간값**, 고성장·적자는 **성숙 마진**(동종 성숙 기업·회사 장기 목표), 성숙은 유지 마진.
- `peak.years` = (경기민감) 과거 사이클에서 정점 수준 마진이 유지된 기간 — 역DCF 막대의 '과거 사이클'과 비교한다. `trough.om` = 비관 시나리오의 바닥 마진.
- `capexR`(설비투자/매출), `daR`(감가상각/매출), `tax`(세율), `g`(영구성장률), `wacc`(할인율), 국내 `conv`(현금 전환율) — 근거가 있을 때만. 없으면 서버가 재무제표·베타로 계산.
- `netCash` = 순현금(현금성 자산 − 차입금, 마이너스면 순차입). **금액 단위 그대로** — 미국 백만 달러, 국내 억원. 국내는 서버에 재무상태표 항목이 없어 최근 분기 공시로 넣는다(없으면 0으로 계산). 미국은 서버가 재무제표로 계산하니 보통 비운다.
- `scen.{bull,base,bear}`: `p` 확률(합 100), `why` 시나리오 한 줄, `g[i]` 그해 매출 성장률, `om[i]` 그해 영업이익률. `i` = 화면 시나리오 표의 열 순서(0 = 첫 해, 보통 다음 회계연도). `null` 이면 그해는 컨센서스(앞 1~3년) 또는 자동 규칙. 컨센서스 해는 웬만하면 두고 그 뒤 해만 채운다.
- `facts` = 화면 '조사 가정 · 근거' 칸 (4~8개). `conf` = `공시` · `보도` · `추정`. `src` 는 `sources` 번호(0부터). 출처 없는 숫자는 쓰지 않는다 — 시나리오 가정 자체는 판단이라 `why` 에 근거를 적는다.
- 파일 안에 증권사·애널리스트 이름은 쓰지 않는다. 회사 목표치는 '목표'라고 쓴다.
